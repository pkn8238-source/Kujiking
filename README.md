# 쿠지킹 (KUJIKING) — 공식 사이트 프로토타입

`kujiking.co.kr`용 **정적 웹사이트**입니다. 빌드 도구 없이 HTML/CSS/JS만으로 동작하고, GitHub Pages 같은 정적 호스팅에 그대로 올릴 수 있습니다.

- 브랜드: 쿠지킹 (KUJIKING) · 도메인: `kujiking.co.kr` (`CNAME` 파일 포함)
- 로고: `assets/logo.png` (원본) · `assets/logo-760.png` (히어로) · `assets/emblem-160.png`, `assets/emblem-400.png` (헤더/푸터 엠블럼)
- 스타일: 옐로/오렌지/레드 + 굵은 검정 외곽선의 팝 브랜드 톤, 모바일 우선 반응형

## 폴더 구조

```
kujiking-site/
├─ index.html            # 전체 화면(홈·뽑기판·당첨 내역·공정성 검증·관리자)
├─ CNAME                 # kujiking.co.kr
├─ .nojekyll             # GitHub Pages Jekyll 처리 비활성화
├─ 404.html              # GitHub Pages용 폴백(홈으로 이동)
├─ assets/
│  ├─ styles.css         # 디자인 시스템 + 반응형
│  ├─ app.js             # 해시 라우터, 뽑기 로직, SHA-256, 관리자, 저장/백업
│  ├─ logo.png           # 로고 원본(투명 배경)
│  ├─ logo-760.png       # 히어로용 경량 로고
│  ├─ emblem-*.png       # 헤더/푸터용 엠블럼(워드마크 제외)
│  ├─ favicon-64.png
│  ├─ apple-touch-icon.png
│  └─ og-image.png
└─ README.md
```

## 로컬에서 보기

```bash
cd kujiking-site
python3 -m http.server 8000
# http://localhost:8000
```

`index.html`을 파일로 직접 열어도 동작하지만, 해시 라우팅·클립보드·Web Crypto는 `http(s)`에서 가장 안정적입니다.

## GitHub Pages 배포

1. 이 폴더를 저장소 루트(또는 `docs/`)에 올립니다.
2. Settings → Pages → Branch를 `main` / `/ (root)`로 지정합니다.
3. 커스텀 도메인에 `kujiking.co.kr`을 입력합니다. (`CNAME` 파일이 이미 포함되어 있습니다)
4. DNS: `A` 레코드 4개(185.199.108.153, .109.153, .110.153, .111.153) + `www`는 `CNAME` → `<사용자>.github.io`
5. HTTPS(Enforce HTTPS)를 켭니다.

배포 후 확인: `/`, `/#/board`, `/#/fairness`, `/#/admin` 접속과 새로고침.

## 관리자

- 주소: `/#/admin`
- 초기 PIN: **0000** (설정 → PIN 변경에서 반드시 변경하세요. 변경하면 로그인 화면의 초기 PIN 안내가 사라집니다.)
- 세션: 브라우저 탭을 닫으면 다시 PIN을 물어봅니다(`sessionStorage`).

### 교환 코드 발급

1. `코드 발급` 탭 → 대상 판 선택(또는 “모든 판”)
2. 1개 / 5개 / 10개 발급
3. `전체 복사` 또는 `문자 발송용 복사`로 스마트스토어(쿠지통령) 구매자에게 전달
4. 코드는 1회용이며, 사용 즉시 `사용` 상태로 바뀌고 재사용이 거절됩니다.

코드 형식: `KJ-XXXX-XXXX` (혼동하기 쉬운 0/O/1/I 제외)

### 판 만들기 / 수정

- 제목, 태그, 1장 가격, 전체 장수, 판매 상태, 라스트원상 문구
- 등급(A~H)별 상품명·수량·굿즈 포인트 — **수량 합계가 전체 장수와 같아야 저장**됩니다.
- 시드: 비우면 자동 생성. 번호 구성(장수·등급)을 바꾸면 새 시드로 다시 봉인되고 기존 개봉 내역은 확인 후 초기화됩니다.
- `판 초기화`: 개봉 내역만 지우고 시드·코드는 유지합니다.

### 백업

- `설정 · 백업` → `JSON 내보내기`로 전체 데이터(판·코드·개봉 내역)를 파일로 저장
- `JSON 가져오기`로 복원 (현재 데이터를 대체)
- 모든 데이터는 **해당 브라우저의 localStorage**에만 있습니다. 기기를 바꾸거나 브라우저 기록을 지우면 사라지므로 정기적으로 백업하세요.

## 공정성 검증 방식 (실제 구현)

1. 판 생성 시 32바이트 난수 시드(`crypto.getRandomValues`)를 만들고
2. `SHA-256(seed)` 해시를 계산해 **판매 전에 공개**합니다(판 화면·공정성 검증 페이지).
3. 번호별 결과는 다음 규칙으로 고정됩니다.

```
for n in 1..N:  h(n) = SHA-256(seed + ":" + n)
tickets sorted by h(n) ascending
prizes assigned in order: A상 → B상 → … (등급별 수량만큼)
```

4. 판이 전량 소진되거나 종료되면 시드를 공개하고, 방문자는 브라우저에서 `crypto.subtle.digest('SHA-256', …)`로 해시와 번호별 배치를 다시 계산해 검증할 수 있습니다.
5. 개봉 기록과 재계산 결과가 다르면 검증 화면에 불일치로 표시됩니다.

## 프로토타입의 한계 (출시 전 확인)

- 결제·서버·회원 기능이 없습니다. 코드 발급과 개봉 기록은 브라우저 저장소 기준입니다.
- 시드가 브라우저 저장소에 함께 있어, 개발자 도구로 미개봉 번호의 결과를 볼 수 있습니다. 실제 운영에서는 **서버에서 시드를 보관하고 개봉 요청 시에만 결과를 내려주는 구조**로 옮겨야 합니다.
- 관리자 PIN은 화면 잠금 수준입니다(서버 인증 아님).
- 푸터의 사업자 정보(상호·대표자·사업자등록번호·통신판매업신고·주소·고객센터)는 **등록 준비 중**으로 표시되어 있습니다. 판매 개시 전 실제 정보로 교체해야 합니다.
- 확률·청약철회 안내 문구는 표준 문구 초안입니다. 판매 전 법률 검토 후 확정하세요.
- 스마트스토어 연동, 알림톡/문자 발송, 배송 조회는 포함되어 있지 않습니다.
